Shelfsmith

Cook what you already have. Shelfsmith tracks a household's pantry, shows the recipes you can make right now, and builds a shopping list for the rest. Scan a grocery receipt, and an AI model adds what you bought.

  • Role: solo developer
  • Status: in TestFlight beta
  • Built: September 2026
  • Platforms: iOS, Android and web from one codebase
Source code Support and privacy

What it does

Cooking

  • Ready to cook shows recipes you can make now, and Almost there shows ones you are one or two ingredients short of.
  • 80 built-in recipes with calories and macros, matched against about 240 ingredients.
  • Diets, allergies, dislikes, and a time limit, set per person.
  • A weekly meal planner, shared with the household.

Household

  • Join a household with a six-character invite code.
  • The pantry and shopping list update live on every phone.
  • Receipt scanning adds groceries without typing.
  • Expiry tracking with a "use these up" reminder at 6 pm local time.

How it works

Recipe matching in one SQL query

A Postgres function joins every recipe against the household's pantry and returns what is missing for each. Staples like salt and oil count as present. Optional ingredients never block a match, and allergens hide a recipe completely.

Results are ranked by favourites, dislikes, and what was cooked recently. Matching deliberately checks whether you have an ingredient, not how much of it, because converting between units needs a density table for every ingredient.

Receipt scanning with AI

  1. Upload. The photo is downscaled on the phone and uploaded to a private storage bucket.
  2. Read. A server-side Edge Function checks who is asking, then sends the image to Claude with the ingredient dictionary. It gets back structured JSON with a confidence rating per line.
  3. Review. The user confirms every line before anything reaches the pantry. The photo is deleted once it has been read.

Security

Every household table routes its Row Level Security policy through one membership check. Joining a household goes through a permission-checked function, so nobody can list households they do not belong to. The AI key exists only on the server.

Subscription status is written only by a webhook verified with a shared secret, so the app cannot grant itself premium features.

Measured cost

I measured the real request size and cut the cost of each scan by about 60%, to roughly 3 cents. I moved to a smaller model, which the human review step makes safe, and removed a prompt cache that never got reused, because receipts are scanned days apart.

Testing the database

The test suite loads every real migration into PGlite, which is Postgres compiled to WebAssembly, so it needs no Docker. It then acts as different signed-in users to prove the access rules hold. For example, a non-member cannot see what a household has expiring, and a housemate cannot read the payer's subscription record.
